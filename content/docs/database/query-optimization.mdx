## Overview

This document presents the performance profiling, benchmark results, and composite index architecture implemented in **Stream 10.2** (Ticket `[10.2] Multi-Tenant Query Profiling, Composite Indexing & RLS Performance Tuning (BR-01)`).

All benchmarks were evaluated against a synthetic dataset of 50 tenants and 806,650 rows across candidate users, assessments, assignments, workspaces, and telemetry activity events using the dedicated profiler script `scripts/db/query-profiler.mjs`.

For the complete technical report, see [`docs/database/query-optimization-report.md`](https://github.com/infinitica-org/hellosmart/blob/dev/docs/database/query-optimization-report.md).

## Migration 0022 Indexes

Migration `0022_performance_composite_indexes.sql` establishes five composite and partial indexes:

```sql
-- 1. Candidate Listing & Sorting Covering Index (BR-01, CA-008)
CREATE INDEX IF NOT EXISTS idx_users_org_role_created
  ON app.users (org_id, role, created_at DESC, id DESC);

-- 2. Tenant Activity Timeline Auditing Index (BR-01, BR-23)
CREATE INDEX IF NOT EXISTS idx_activity_events_org_at
  ON app.activity_events (org_id, at DESC);

-- 3. Active Workspace Autosave Sweeper Partial Index (BR-11, BR-23)
CREATE INDEX IF NOT EXISTS idx_workspaces_active_autosave
  ON app.workspaces (last_activity_at ASC)
  WHERE status IN ('connected', 'disconnected');

-- 4. Auto-Submit Sweeper Partial Index (BR-08, BR-23)
CREATE INDEX IF NOT EXISTS idx_assignments_auto_submit
  ON app.assignments (deadline_at ASC)
  WHERE status IN ('in_progress', 'disconnected') AND deadline_at IS NOT NULL;

-- 5. Expired Candidate Retention Purge Partial Index (BR-26, BR-27)
CREATE INDEX IF NOT EXISTS idx_users_deleted_retention
  ON app.users (org_id, deleted_at ASC)
  WHERE status = 'deleted' AND deleted_at IS NOT NULL;
```

## Row-Level Security (RLS) Mechanics

PostgreSQL Row-Level Security enforces tenant isolation by rewriting application queries executed as `hs_app`. The policy structure in query plans manifests as:

```text
Filter: ((users.org_id = (current_setting('app.org_id'::text, true))::uuid) OR app.is_platform())
```

### Key Takeaway on Function Inlining

Because `app.is_platform()` is a `plpgsql` function, PostgreSQL cannot inline it. On unindexed queries, PostgreSQL must evaluate `app.is_platform()` per row. When queries are indexed leading with `org_id`, the engine uses the index condition on `current_setting('app.org_id')` to filter candidate tuples prior to evaluating the row filter, eliminating CPU overhead.
