# Branching and environments

```
feat/CO-012-…  ─┐
fix/CA-009-…   ─┼─▶  dev  ──(auto)──▶  DEV  (dev.hellosmart.ai)
sec/…          ─┘     │
                      │  promotion PR  dev → qa
                      ▼
                     qa   ──(auto)──▶  QA / STAGING  (AWS EC2 · qa.hellosmart.ai)
                      │
                      │  release PR  qa → main  (or dev → main; QA sign-off required)
                      ▼
                    main ──(approval)──▶  PRODUCTION  (AWS ap-south-1 · app.hellosmart.ai)
                      ▲
hotfix/… ─────────────┘  (then back-merge main → dev & qa)
```

## Environments
| Env | Branch | Infra | Data | Who deploys | Access |
|---|---|---|---|---|---|
| Local | any | Docker Compose (`pnpm infra:up`) | fixtures | you | you |
| Dev | `dev` | AWS (`dev.hellosmart.ai`), ECS / Docker Compose | fixtures (resettable) | CI on every merge to `dev` | team only |
| QA / Staging | `qa` | AWS EC2 / ECS (`qa.hellosmart.ai`), Sysbox, LocalStack, Mailpit | fixtures (resettable) / masked clones | CI on promotion PR `dev → qa` | team IP allowlist + basic auth |
| Production | `main` | AWS Multi-AZ (ECS, RDS PostgreSQL 16, EC2 Sysbox hosts, EKS gVisor) | real | CI after approval on `production` environment | public |

See the full target cloud topology and CIDR allocation across Dev (`10.1.0.0/16`), QA (`10.2.0.0/16`), and Production (`10.0.0.0/16`) in [AWS Production Migration & Architecture](/docs/architecture/aws-migration).

## Weekly rhythm
| Day | What |
|---|---|
| Mon 10:00 | Release PR `qa → main` merged (after QA sign-off) → prod deploy → smoke |
| Mon | Sprint planning |
| Tue–Wed | Build; merges to `dev` deploy to Dev continuously; promote `dev → qa` for integration |
| Wed 18:00 | Integration check on QA (all departments' work together) |
| Thu | QA regression on QA env (`qa.hellosmart.ai`) |
| Fri | QA sign-off, demo, retro; release PR opened |

## Branch protection (set in GitHub → Settings → Rules)
**`main`**
- PRs only; no direct pushes, no force pushes, no deletion
- Required checks: `ci/*`, `security/*`
- 2 approvals: Architecture & Platform + QA
- Only from `qa`, `dev` (approved release PR), `release/*`, or `hotfix/*`
- Linear history, signed commits required
- Deployments gated by the `production` environment (required reviewer: Architecture & Platform)

**`qa`**
- PRs only from `dev` or `hotfix/*`; no direct pushes, no force pushes
- Required checks: `ci/*`, `security/*`

**`dev`**
- PRs only; no direct pushes, no force pushes
- Required checks: `ci/*`, `security/*`
- 1 approval from CODEOWNERS (2 for sensitive paths)
- Branch must be up to date before merge; squash merge only

## Hotfix
1. `git checkout -b hotfix/<ID>-slug origin/main`
2. Fix + test; PR to `main` (Architecture + QA approval).
3. After deploy: PR `main → qa` and `main → dev` the same day.

## Feature flags
Work that isn't complete merges to `dev` behind a flag (default off in prod). Flags live in `app.feature_flags` per org; removing a flag is a ticket.
